# Header.jsx: extract auth-effect hook + controller-owned handlers

`Header` (`frontend/assets/js/components/common/header/Header.jsx`, currently 51 NLOC) already delegates markup to `HeaderHelper` — its bulk is hook/effect wiring and a handlers-object literal, not JSX. Two extractions, both needed to clear the limit:

1. **Custom hook for the auth-lifecycle effect.** The `useEffect(() => {...}, [])` currently spanning roughly lines 51-84 — `controller.checkStatus()` chained into `viewAsController.checkAvailability(...)`, the `AuthEvents`-subscribed `handleAuthChanged` (tracks `lastLoggedInRef`, calls `setLoggedIn`, and calls `controller.recheckAuthState(viewAsController)` on a genuine transition), the `AccessEvents`-subscribed `handleFacadeChanged` (`setFacadeEnabled`), and `controller.buildRouteEffect()`'s cleanup — moves into a new custom hook, `useHeaderAuthEffect`, under a new `frontend/assets/js/components/common/header/hooks/` folder. This follows the existing custom-hooks convention already used under `frontend/assets/js/components/resources/character/pages/shared/hooks/` (see e.g. `useProfilePhotoActions.js` for the "hook takes external setters/collaborators as params, doesn't necessarily own all its own state" shape — `HeaderController` already owns `setLoggedIn` internally, so the hook can call `controller.setLoggedIn(...)` rather than needing a separate `setLoggedIn` param). Params: at minimum `controller`, `viewAsController`, `setFacadeEnabled`, and the current `loggedIn` value (to seed the hook's internal `lastLoggedInRef` — do not lift that ref out of the hook). Returns nothing; it's an effect-only hook, called for its side effect like the existing `useEffect(() => gameAccessController.buildEffect(...), [route.gameSlug])` call that stays in `Header.jsx` unchanged (only the *first* effect moves — the second, game-access effect, is already short and stays as-is).
2. **Controller-owned handlers builder.** The handlers-object literal built inline and passed as `HeaderHelper.render`'s second argument (the `onLoginClick`/`onLogoffClick`/`onModalClose`/`onLoginSuccess`/`onSendTestEmailClick`/`onLanguageChange`/`onViewAsClick`/`onViewAsModalClose` block) moves onto `HeaderController` as a `buildHandlers(viewAsController, loggedIn)` method, since every one of those callbacks already just wraps an existing `HeaderController`/`viewAsController` method. `Header.jsx` then calls `controller.buildHandlers(viewAsController, loggedIn)` in place of the inline object literal.

After both extractions, `Header.jsx` should read as: state declarations, controller instantiations, the (now single-line) `useHeaderAuthEffect(...)` call, the unchanged game-access effect, and a `return` delegating to `HeaderHelper.render(state, controller.buildHandlers(...))`.
